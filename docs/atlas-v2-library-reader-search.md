## Indexing + content-update procedure (WP5)

1. Content changes happen ONLY in the content repo (never in this website branch) and get a new tagged release.

2. Copy the new release's chapters/manifests/concepts (read-only) to a local working copy.

3. Run: `python3 scripts/atlas-v2/generate-data.py --content-dir <copy> --repo .` — this regenerates `lib/atlas-v2/chapters.ts`, `domains.ts`, `related.ts`, `public/atlas-v2/search-index.json`, and this mapping section.

4. Re-run the checks in `scripts/atlas-v2/checks.py` (chapter count = 57, link check, search queries) and rebuild.

5. Deploy to STAGING ONLY via `vercel-file-deploy-staging.py`; never the production uploader; production stays unchanged until owner tap.


## Original notes + provenance (honesty labels)

- Sources lines are copied verbatim from the master (e.g. “V1 Research Edition”, “Industry Evolution Edition”).

- Paragraphs labelled “From the original pages” paraphrase handwritten sources; “Technical expansion and corrections” is editorial explanation, not manuscript text. Those labels are preserved in the reader.

- Original-note files are linked BY FILENAME. SHA verification is NEVER claimed: the recorded master SHAs are known not to match the stored files (0/136), so no SHA is displayed as proof. The filename is the working link key.

- Images are local build assets (`/atlas-images/<filename>`, copied at build time from the verified staging asset set, 136 files); lazy-loaded; never hotlinked.


## Search (WP5)

- Build-time static index (`public/atlas-v2/search-index.json`): titles, headings, concepts (via chapter text), and full body text (paragraphs, lists, table cells, diagram text). No vector DB, zero budget.

- Results page: `/search?q=…` — query persists in the URL and is shareable; snippets come from the first matching body paragraph; highlighting is done by React text-splitting (no injected HTML).

- Search box appears on the library page and on every chapter-reader page.

## Reader modes — what changes, what does not (WP4)
- Both modes render the SAME canonical chapter body. Explore & Learn collapses only paragraphs the master itself labels "Technical expansion and corrections" into per-block "Technical depth" disclosures, plus diagrams/tables/original-notes sections into disclosures; a single "Expand all technical detail" control opens them all, and Research & Engineering mode shows everything uncollapsed. Switching modes does not reload the page or change the URL, so scroll place is kept; section anchors are identical in both modes.
- The master contains no structured code blocks (only 5 prose paragraphs mentioning commands/tools); command mentions therefore remain verbatim in prose, not invented into code blocks. Step flows are paragraphs containing "→" plus "System walkthrough" paragraphs, styled as flows without altering text.
