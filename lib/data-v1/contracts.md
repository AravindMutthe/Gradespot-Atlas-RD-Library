# Atlas public data contracts — `/data/v1/*` (design artifact, NOT a live API)

**Status: CONTRACT DESIGN ONLY — publication status: NOT PUBLISHED.**
No file under `public/data/` is generated by this step, and no URL under
`/data/v1/*` is served by the static export. The contracts below exist as
documentation (this file) and typed schemas (`schemas.ts` in this same
directory, which is NOT imported by any page and therefore contributes no
runtime code and no public JSON). Nothing here implies a live API exists:
there is no runtime endpoint, no query handling, no authentication, and no
uptime or availability claim. A future step that wants publicly accessible
JSON files must make that publication decision explicitly, with the
publication status recorded in the files themselves and in the step report.

## 1. Versioning (two independent identities — never conflated)

- **Schema version** (`schemaVersion`, e.g. `"1.0"`): compatibility of the
  JSON shapes defined here. A breaking shape change (field removed, field
  renamed, slug renamed, category added) requires a major schema bump.
  Additive optional fields are minor.
- **Content release** (`contentRelease`, e.g. `"v1-consolidated-001"`):
  identity of the Atlas content snapshot, taken from the release manifest
  (`/release.json`). A content release is NOT an API compatibility
  guarantee: new content may arrive under the same schema version, and a
  schema bump does not by itself change the content release.
- Every emitted document (if publication is ever decided) MUST carry both
  `schemaVersion` and `contentRelease`, plus `generatedAt` (build time,
  UTC) and `canonicalBase` (the site base URL the canonical URLs resolve
  against).

## 2. Provenance (every document, every record)

- `provenance`: one of `canonical-chapter` (text verified against the
  consolidated master), `editorial` (added explanatory material, labelled
  as added), `proposed` (design proposal, not published content).
- Original-note material is NEVER included in a public data document
  unless its publication and privacy flags have been cleared by the owner.
  Today those flags are uncleared for the 187 referenced note assets, so
  no note image, scan, transcription, or identifier appears in any
  contract example or emitted document.
- Restricted material must not exist in any public JSON, index, sitemap,
  feed, or sourcemap — unrenderable, not merely hidden by styling
  (DES-07 sanitized-projection rule).

## 3. Surfaces (proposed — none served today)

| Surface | Content | Publication status |

| `/data/v1/chapters/{slug}.json` | Sanitized chapter data — OPTIONAL, only if external machine-readable access is genuinely needed | NOT PUBLISHED (design only) |

| `/feed.xml` | Approved publication updates | NOT EMITTED (see feed decision below) |
| Pagefind-generated index (or evaluated equivalent) | Search index over approved public content only | NOT ADOPTED (see search evaluation) |

## 4. Static-export behavior (if publication is ever decided)

- Documents are generated at build time from the same allowlisted public
  projection as the pages, and copied into the static export as plain
  files. No server code runs at request time.
- A document's canonical URL is `canonicalBase + path` with a trailing
  slash for pages; data files carry no trailing slash (they are files,
  not routes) and MUST NOT be listed in `sitemap.xml` (the sitemap lists
  canonical page routes only).
- Documents are immutable per content release: a new release regenerates
  them; old files are never edited in place.
- No document may contain: note image binaries or paths, note
  transcriptions, private identifiers, unpublished or draft chapters,
  invented publication dates, or claims about rankings, traffic, revenue,
  or partnerships.

## 5. Feed decision (recorded, not deferred silently)

`/feed.xml` is NOT emitted. Reasons, all checkable: (a) canonical chapter
data carries no verified per-chapter publication date, and inventing
dates is forbidden; (b) a feed is an editorial decision about what counts
as an "update", and no such decision has been made; (c) a feed must not
expose unverified or private material, and the pending note-asset and
taxonomy items make a chapter feed premature. When a feed is eventually
decided, it may expose titles, summaries, dates, and links only — never
unverified or private material — and its first emission must be recorded
as an editorial decision with its date source named.

## 6. What this step deliberately does NOT do

- No public JSON file is emitted under `/data/`.
- No `/feed.xml` is emitted.
- No Sources route is added or changed (deferred; see report).
- No note asset is ingested, published, or reclassified.
- No taxonomy mapping decision is made (grouping stays configurable).
- No new editorial chapter copy is written; the 56 auto-sliced chapter
  descriptions are unchanged.
